# Data model and data dictionary

Master-data model and field-level dictionary derived from the four ADABAS DDMs, with usage, lineage, source-key, and HCM-mapping columns.

| | |
|---|---|
| **Capability** | Data model and data dictionary |
| **Why it matters to an SI implementing an HCM** | HCM Data Loader mapping starts from a definition of master data: every attribute, its format, its descriptor role, whether it is used, and what it maps to. Unused and ambiguous fields are as important as used ones. |
| **Builds on** | `../../docs/data-dictionary.md`, `../../tools/generate_data_dictionary.py`, `../../SunnyIslands/Natural-Libraries/CRUISE16/DDMs/*.NSD`, `../../tools/analyze_disposition.py` (field-usage matrix) |
| **Maturity** | Demonstrated (dictionary is generated from the DDMs and drift-tested) |

## Contents

| Artifact | What it is | How it is produced | Maturity |
|---|---|---|---|
| `data-model.md` | Entity-relationship view, file roles, keys and descriptors, ISN versus business key, relationships via `ID-CUSTOMER` / `ID-CRUISE` / `ID-YACHT`, first-name lineage, sample-to-FPPS analogy, traceability | Authored against opened source lines | Demonstrated for the sample; analogy rows labelled (designed) |
| `data-dictionary-hcm.md` | Field-level dictionary: one row per DDM field with format, descriptor, referenced-by-executable-code, lineage, candidate Oracle HCM object/attribute, mapping note, cleansing rules | Generated by `generate_dictionary_hcm.py` from `tests/harness/source_parser.all_ddms()`, `tools/analyze_disposition.analyze()['ddm_field_usage']` and the 07 rule catalogue; the HCM analog, mapping and lineage columns are authored annotations the generator requires for every field | Demonstrated (generated, `--check` drift-tested); HCM analog columns (designed) |
| `generate_dictionary_hcm.py` | Generator with `--check`; fails if any DDM field lacks an annotation, if an annotation names a field that no longer exists, if a cleansing rule is keyed to an unknown field, or if the committed Markdown differs | Python generator - a build tool, never a rewrite target | Demonstrated |
| `diagrams/` | `er-model.mmd`, `booking-relationships.mmd`, `first-name-lineage.mmd` (Mermaid source) with `.png` / `.svg` exports rendered by `@mermaid-js/mermaid-cli` | Extracted from `data-model.md` | Demonstrated |

## What the dictionary tells an SI that the DDM alone does not

| Question in a mapping workshop | Where the answer is | Example from the sample |
|---|---|---|
| Is this field actually used? | "Referenced by executable code" column (static, name-based) | `FIRST-NAME-2`, `TITLE`, `FORM-OF-ADDRESS`, the `PHONE` group and all `DEPOSIT` / `PAYMENT-OF-BALANCE` children are unreferenced in analyzed scope |
| Which of two look-alike columns is the survivor? | "Lineage notes" column with `path:lines` | `FIRST-NAME-OLD` is persisted (`CUNEW-N.NSN:48`, `CUMOD-N.NSN:53`); `FIRST-NAME-1` is adapter-only and commented out of the DB view (`NCDATA-L.NSL:56`) |
| Which field is the source key and which is just an index? | `data-model.md` "Keys and descriptors"; `Desc` column | `SURNAME`, `COUNTRY`, `ZIP-CODE`, `CITY`, `SEX` are descriptors but not keys; the ISN is neither |
| What breaks the load? | "Cleansing rules" column, resolved in `../07-master-data-cleansing/cleansing-rules.md` | `CRUISE-STATUS` is an A1 holding a digit (CR-04); `EMAIL` is an MU where only occurrence 1 has code meaning (CR-06) |
| Can the analyzer be wrong? | "ambiguous" marker and lineage note | `LENGTH` in `NCYACHT` and the `NAME` / `ADDRESS` / `PRICES` group headers collide with Natural keywords; `FIRST-NAME-1`'s `RDCRUISP` hit is a PDA-field name match |

## Reproduce

```bash
# from the repository root
python3 fpps-hcm-modernization-deliverable/03-data-model-data-dictionary/generate_dictionary_hcm.py          # regenerate
python3 fpps-hcm-modernization-deliverable/03-data-model-data-dictionary/generate_dictionary_hcm.py --check  # exit 1 on drift
python3 tools/generate_data_dictionary.py && git diff --exit-code docs/                                       # the source-side dictionary it builds on
```

## How an SI consumes this

1. Open `data-dictionary-hcm.md` next to the HCM Data Loader mapping workbook. Each row is one source attribute; copy the "Candidate HCM object" and "Candidate HCM attribute" columns into the target side as the starting proposal, then confirm each against the Business Object Details page of the target release (Data Exchange work area) - the dictionary's HCM columns are (designed) until that confirmation.
2. Treat the "Referenced by executable code" column as a routing decision: `yes` rows go into the workbook; `no - unreferenced in analyzed scope` rows go to `../10-migration-disposition-dead-code/` for a disposition decision before any mapping effort; `ambiguous` rows need a human read of the cited lines.
3. Use the "Cleansing rules" column to pull the matching rule rows from `../07-master-data-cleansing/cleansing-rules.md` into the data-quality section of the workbook, and run `../07-master-data-cleansing/harness/cleanse_reconcile.py` to see what each rule does to synthetic data.
4. Take `data-model.md` "Keys and descriptors" into the source-key design: business keys (`PERSON-ID`, `CONTRACT-ID`, `CRUISE-ID`, `YACHT-ID`) become `SourceSystemId` values with a single `SourceSystemOwner`; the ISN is never carried.
5. Feed the relationship table (`ID-CUSTOMER`, `ID-CRUISE`, `ID-YACHT`) into HDL load ordering: parents (`NCYACHT` → `NCCRUISE` → `NCCUSTOMER`) before the transaction file (`NCCONTRACT`), one object type per `.zip`, errors fixed before the next file.
6. Put the first-name lineage table into the acceptance-test plan as a named case: the HCM `FirstName` must equal `FIRST-NAME-OLD` where present and `FIRST-NAME-1` otherwise, and every conflict must appear in the steward queue.

## Synthetic data and scope

All evidence in this directory is produced from the Sunny Islands Cruise sample sources and synthetic data in `../../tests/harness/`. No production system, production data, or FPPS source is used or required. FPPS statements are analogies to a Software AG Natural 9.x / ADABAS 8.6 estate (~7M lines of Natural, 100k+ modules, ~7,800 JCL jobs); nothing here proposes a language rewrite. `generate_dictionary_hcm.py` is a generator that builds the mapping-workbook input; it is not a rewrite target.
